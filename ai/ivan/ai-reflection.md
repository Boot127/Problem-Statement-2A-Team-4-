[Throughout this project, the AI was useful to me mainly because it helped speed up parts of the development process that I was not as confident with. I used AI to help understand the existing project structure, build parts of my Review and Approval Workflow, troubleshoot the errors, and test whether my features were actually working, instead of having to figure out every file and connection from scratch, AI helped point me towards which frontend pages, API services, backend routes and database logic were involved. This gave me more time to focus on whether the feature matched our project requirements instead of just trying to get code to run.
One area where AI added a lot of value was testing and debugging. After my initial Review and Approval Workflow was implemented, I asked AI to check the feature rather than assuming that it was finished just because it could run. The tests showed that the main backend workflow was working, including CRUD operations, the status transitions, comments, publishing and notifications. However, it also found problems that I did not noticed myself. For example, notifications were being created in the database but there was no proper frontend interface for the user to see them. The version history also existed, but it only showed basic information such as the version number and date. This showed me that having working backend code does not necessarily mean that a feature is complete from the user's point of view.
I also learned that I should not blindly accept everything AI generates. One significant issue was the database implementation. My Review Workflow was initially using SQLite independently, while other parts of the team's application could use a different database such as PostgreSQL/Neon. Although my features worked when tested by itself, I realised this could become a major integration problem because a review might reference a work permit that exists in another database. I therefore asked AI to inspect the existing project architecture and modify the implementation so that my feature could work with the team's actual data instead of simply accepting the original solution. This was important because an isolated feature would not meet the purpose of building a fully integrated full stack application.
Another AI suggestion that I significantly modified was the use of automatically generated sample reviews. This was convenient during development because I could immediately see data on the screen, but further checking showed that some sample reviews could reference target records that did not actually exist. I decided that keeping this behaviour for the final system was not a good idea. For a compliance related system, showing a review for a record that does not exist could be misleading. I therefore chose to remove or change this behaviour rather than keeping it just because it made the application easier to demonstrate.
AI also helped me improve smaller areas such as validation, error handling and workflow restrictions. For example, the review status should not simply be editable to any value. The user should have to follow the proper process, such as Pending to In Review, followed by Approved, Changes Requested or Rejected. Publishing should also only be possible after approval. Having AI identify and test these edge cases helped me understand that good development is not only about making the normal flow work, but also preventing users from doing things that should not be allowed.
Overall, I found AI most valuable when I treated it as a development assistant rather than something that could complete the project perfectly on the first attempt. It helped me generate and understand code faster, find issues I would probably have missed, and test different parts of my feature. At the same time, this project showed me that AI generated solutions still need to be checked against the actual requirements and the rest of the team's system. Some suggestions looked correct when viewed individually but needed to be changed once I considered integration, usability and real user behaviour. The biggest thing I learned was that using AI effectively is not just about asking it to generate code. I still needed to review what it produced, question whether the solution made sense for our project, test it, and ask for changes when it did not.
